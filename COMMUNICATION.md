# Взаимодействие

## Два разных протокола, не один

- **Агент ↔ инструмент** — покрыто механизмом `skills/`: агент вызывает способность, способность выполняется, результат возвращается.
- **Агент ↔ другой агент** — физический канал для Engineer ↔ Researcher существует и дважды проверен реальным прогоном (2026-08-12). Постоянным правилом взаимодействия пока не является — `Proposal` в `DECISIONS.md`, ждёт отдельного явного решения владельца. Другие пары агентов — канал не проверен вообще, не предполагается по аналогии.

Смешивать эти два протокола в одном механизме — источник путаницы: правило, разумное для вызова инструмента (агент полностью управляет вызовом), не обязательно разумно для передачи задачи другому агенту (нужна договорённость о том, кто владеет финальным ответом).

## Engineer ↔ Researcher — что реально проверено (факт, не правило)

Прямой вызов, без владельца как реле, дважды реально прогнан 2026-08-12. Ниже — описание того, что произошло и было проверено технически. Станет ли это постоянным способом работы — решение владельца, не принято.

- **Вызов**: Engineer порождает фонового агента с обязательным контрактом в промпте — прочитать устав целевого агента (`CLAUDE.md`→`HOME.md`→`MISSION.md`) прежде чем делать что-либо, затем узкий research brief с критерием достаточности, зафиксированным до запроса (формат `OPEN_QUESTIONS.md`).
- **Кто владеет финальным ответом**: Engineer — сверяет результат с зафиксированным критерием, не сам воркер.
- **Уточнение**: адресный повторный вызов того же агента с конкретно названным пробелом («по X недостаточно, уточни X») — не пересказ задачи с нуля, продолжает с полной историей.
- **Эскалация владельцу** — только когда Engineer дошёл до решения, требующего его слова (Locked-переход, высокий радиус поражения, граница Craft vs Engineering) — не для самого исследовательского цикла.
- **Что остаётся у Researcher** — находки пишутся в её собственные файлы (`knowledge/`, `memory/`, её `OPEN_QUESTIONS.md`) по её же правилам роста знания, не в промежуточный формат Engineer.

## Когда этот файл дополнять дальше

Механизм проверен и закреплён только для пары Engineer↔Researcher. Другая пара агентов (субагенты, параллельные инстансы) — та же дисциплина («сначала доказать физический канал, потом закреплять правило») применяется отдельно, не наследуется автоматически.
