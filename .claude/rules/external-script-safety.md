# Изоляция при запуске чужого скрипта/парсера

Применяется к любому исполняемому файлу (Python/shell/JS), который пришёл не из этого дома —
клонированный скилл-репозиторий (`git clone` во время импорта), скачанный установщик,
скрипт из чужой библиотеки. Повод: за эту сессию в дом попали реальные исполняемые файлы
из внешних источников (`humanizer/references/validate-package.py`, 8 скриптов
`skill-creator` — `run_eval.py`, `package_skill.py` и др.) — ни один ещё не запускался,
но правила запуска для них не было прописано нигде, кроме общей интуиции.

## Правило

1. **Прочитать скрипт целиком до первого запуска.** Не «выглядит нормально по имени файла» —
   реально открыть и прочитать код: что он пишет, куда, какие сетевые вызовы делает, какие
   команды исполняет через `subprocess`/`os.system`/`eval`. Скрипт, который не прочитан
   полностью, не запускается — не бывает исключения «он маленький».
2. **Первый запуск — в scratchpad, не в рабочей папке агента.** Скопировать в
   `AppData/Local/Temp/claude/.../scratchpad` (или его аналог для текущей сессии) и выполнить
   там. Только если результат ожидаем и без побочных эффектов вовне scratchpad — переносить
   в реальную папку агента.
3. **Первый запуск — на синтетических/примерных данных, не на реальных бизнес-данных.**
   Данные клиентов, реальные токены, реальный `feed.xml`/`clients_index.db` и т.п. — не
   первый вход для непроверенного скрипта, даже если сам скрипт заявлен как «только читает».
4. **Python — только в собственном `venv`/через явный `requirements.txt` агента,** не
   `pip install` в системный интерпретатор. Тот же принцип, что уже действует для
   `AI Legal Constructor` (Data Contract/Tooling Inventory, `skills/repository-design/SKILL.md`)
   — распространяется и на скрипты, унаследованные из чужого скилла, а не только на
   собственный код агента.
5. **Сетевой доступ и запись за пределы scratchpad — решение, не умолчание.** Если по итогам
   чтения (пункт 1) скрипт делает сетевой запрос, пишет файл вне scratchpad, или запускает
   другой процесс — это отдельное решение с тем же уровнем внимания, что любое другое
   действие с высоким радиусом поражения (пропорциональная проверка радиусу — не автоматическое
   «раз он в комплекте скилла — значит можно»).
6. **Секреты не в зоне видимости скрипта.** Скрипт из внешнего источника не запускается в
   рабочей директории, где физически лежат `.env`/токен-кэши — тот же принцип изоляции
   секретов, что уже применяется перед запуском Codex-аудита
   (`instructions/agent-verification-via-codex.md`, п.2), распространённый на любой внешний
   исполняемый код, не только на LLM-инструмент.

## Что не требует этой процедуры

Скрипты, написанные самим Engineer (или другим агентом дома) под свою же задачу —
`calculate.py` Traffic Manager и подобные — не «внешний источник», проверяются обычным
тестовым прогоном (`verification-before-completion`), не этим протоколом.
