# Verification Before Completion (Iron Law)

## Принцип

Никаких утверждений об успехе, закрытии задачи или готовности кода без прямого свежего доказательства (вывода консольной команды, диффа или теста).

```text
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

## Алгоритм проверки (Gate Function)

Перед тем как объявить статус готовности или выразить удовлетворение результатом:

1. **Команда:** определить, какая именно команда доказывает работоспособность (тест, линтер, билд, статус git).
2. **Запуск:** выполнить полную команду в терминале целиком.
3. **Чтение:** прочитать полный вывод, проверить код возврата (exit code 0) и количество ошибок.
4. **Фиксация:** заявлять об успехе только вместе с реальным выводом консоли. Пропуск шага приравнивается к дезинформации.

## Запреты и красные флаги (Red Flags)

- Запрещены формулировки: «должно работать», «скорее всего готово», «выглядит правильно».
- Запрещено объявлять задачу завершенной или делать коммит/PR без запуска верификации.
- Запрещено слепо доверять отчетам субагентов об успехе: факт проверяется лично через `git diff` и запуск тестов.

## Матрица обязательных доказательств

| Заявление | Требуемое доказательство | Что недопустимо |
|---|---|---|
| Тесты прошли | Вывод команды тестов: 0 сбоев | Прошлый прогон, предположение |
| Линтер чист | Вывод линтера: 0 предупреждений/ошибок | Частичная проверка |
| Сборка успешна | Вывод билда с кодом выхода 0 | Успех линтера |
| Баг исправлен | Повторный прогон сценария, воспроизводившего баг | Изменение кода без запуска сценария |
| Субагент закончил | Личная проверка изменений через Git diff | Вера отчету субагента на слово |
