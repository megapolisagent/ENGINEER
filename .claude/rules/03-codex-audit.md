# Codex Deep Audit Protocol

Полный аудит агента через внешний `codex-cli` (проверено на `codex-cli 0.147.0`; флага `--file` у `codex exec` нет — бриф подаётся через stdin).

## Когда
После сборки или реорганизации любого агента экосистемы.

## Команда
```bash
codex exec -C "<путь к папке агента>" - < .claude/rules/03-codex-audit.md
```
`-C` задаёт рабочую папку проверяемого агента.

## Риск секретов — проверить перед первым запуском
Бриф просит Codex читать проект без исключений, включая `.env`/кэши токенов. Содержимое таких файлов уходит в контекст модели-провайдера Codex, если не используется `--oss`/локальный провайдер.
Перед запуском на репозитории с реальными ключами: согласовать с владельцем допустимость, либо временно вынести `.env`/токен-кэши за пределы проверяемой папки на время аудита.

## БРИФ (передаётся Codex через stdin — текст ниже адресован Codex, не Инженеру)

Ты — независимый системный аудитор и эксперт по архитектуре LLM-агентов. Тебе на вход передаётся репозиторий агента — текущая рабочая директория. Проведи тотальный аудит всех файлов и папок без исключений: код, документация, справочники, кэши, временные файлы, логи, тестовые данные, конфигурации.

### Блок 1. Смысловая архитектура (Craft & Role)
- Целеполагание и результат: понятен ли осязаемый бизнес-результат, который агент сдаёт владельцу?
- Полнота инструкций: достаточно ли знаний для автономной работы в нише? Есть пробелы в сценариях?
- Tone of Voice: отсутствует роботизированная канцелярщина?
- Защитные границы: зафиксировано ли, чего агент НЕ имеет права делать без подтверждения владельца?

### Блок 2. Инженерия и инфраструктура (Engineering)
- Работоспособность кода: синтаксические ошибки, устойчивость к сбоям, тайм-ауты, повторы запросов.
- Синхронность с API/схемами (Swagger/OpenAPI/XSD).
- Безопасность данных: нет хардкода токенов/ключей/паролей. При обнаружении секрета — указывать только путь и факт хардкода, НЕ цитировать сам секрет.
- Валидация выходов (Exit Gates) перед сохранением/публикацией.

### Блок 3. Аудит чистоты и структуры (Hygiene & Bloat Check)
- Паразитный контекст: файлы, раздувающие контекстное окно без смысловой нагрузки.
- Мёртвые файлы, дубликаты одних и тех же инструкций под разными именами, старые логи.
- Забытые тестовые артефакты (сырые JSON, временные выгрузки).
- Архитектурный дрейф: папки/модули, не относящиеся к роли агента.

### Формат заключения
1. **ИНВЕНТАРИЗАЦИЯ ПРОЕКТА** — число проверенных файлов/папок; дерево проекта с назначением каждого раздела.
2. **ТАБЛИЦА ЗАМЕЧАНИЙ** — CRITICAL / WARNING / TRASH-REDUNDANT.
3. **СПИСОК «ЧТО УДАЛИТЬ ПРЯМО СЕЙЧАС»** — точные пути к файлам и папкам.
4. **ИТОГОВЫЙ ВЕРДИКТ** — READY или ACTION REQUIRED.
