# Правила памяти и самообучения

> Как агент помнит владельца и становится точнее от раза к разу.

---

## Три уровня памяти

### Уровень 1 — Постоянная память (`MEMORY.md`)
Что верно ВСЕГДА. Лимит на объём, только самое главное.
- **Читать:** всегда при старте сессии.
- **Писать:** появился новый постоянный факт — агент сразу дописывает сюда одной строкой.

### Уровень 2 — Дневник (`memory/ГГГГ-ММ-ДД.md`)
Хроника по дням: что делали, где остановились. Один файл = один день.
- **Читать:** последний дневник при старте.
- **Писать:** в конце сессии — итог дня.
- **Правки владельца** идут в отдельный файл `memory/feedback_<тема>.md` (см. ниже).

### Уровень 3 — Копилка знаний (`knowledge/`)
Базы, которые растут по темам, специфичным для специализации.
- **Читать:** под конкретную задачу, точечно.
- **Писать:** когда накопилось что-то полезное на будущее.
- **Только актуальное состояние, не лог изменений.** Заменили, удалили или обновили скилл/правило/файл — фиксируем новое состояние на месте той же страницы, не пишем статью о том, как и почему что-то поменяли. История изменений — в `git log`, не здесь. Подробности — `.claude/skills/knowledge-wiki/SKILL.md`, «What this deliberately does not do».

---

## Правило дневника (обязательно)

Каждый новый день работы заводи дневник. Создай файл `memory/ГГГГ-ММ-ДД.md`. В конце сессии допиши три строки:

1. **Что сделали** — какой результат получили.
2. **Что осталось** — что доделать в следующий раз.
3. **Решения** — что важного решили.

Если файла за сегодня ещё нет — создай его сам на первом рубеже, не жди команды.

Шаблон дневника:

```markdown
# Дневник ГГГГ-ММ-ДД

## <Главный результат дня одной строкой>

### Что сделали
- ...

### Что осталось
- ...

### Решения
- ...
```

## Самообучение — как агент копит знания от раза к разу

Агент не просто помнит — он учится. После каждой работы важное отправляется в нужный ящик, без спроса.

| Когда | Куда пишем |
|---|---|
| Владелец поправил агента («не так», «переделай») | `memory/feedback_<тема>.md` |
| Владелец 2+ раза спросил одно и то же | нужный файл в `knowledge/` — готовый ответ, чтобы не переспрашивать |
| Понят устойчивый вывод из опыта | `knowledge/lessons-learned.md` |

> Специализация, подключённая поверх Foundation, может расширить эту таблицу своими триггерами и своими файлами `knowledge/` — эта таблица содержит только общий минимум.

### Шаблон правки (`memory/feedback_<тема>.md`)

```markdown
# Правка: <тема>
Дата: ГГГГ-ММ-ДД
Было: <что агент сделал не так>
Правка владельца: <что он сказал изменить>
Правильно: <как теперь делаем>
```

Смысл: один раз поправил — агент запомнил навсегда и больше не наступает на те же грабли.

## Когда источники расходятся

Если `MEMORY.md`, дневник (`memory/`) и `knowledge/` говорят разное про один и тот же факт — не выбирай молча. Порядок доверия:

1. **`MEMORY.md`** — курируется, капнута, предполагается актуальной; источник истины по умолчанию.
2. **Более свежая запись в дневнике `memory/`**, чем последнее обновление `MEMORY.md` по той же теме — вероятно, `MEMORY.md` просто не успели обновить; используй дневник, но допиши то же самое в `MEMORY.md`.
3. **`knowledge/`** — наименее приоритетно: копится по ходу работы, обновляется реже остальных.

Расхождение — не повод выбрать что-то на глаз. Если оно существенно меняет ответ — оцени по Входному гейту задачи (CLAUDE.md §3) и зафиксируй разрешение прямо в `MEMORY.md` (если факт постоянный) или в нужной странице `knowledge/` (если это тема, не общий факт) — не спрячь его в очередной правке одного файла молча.

## ⚠️ Важно: две памяти — не путать

У среды выполнения может быть своя встроенная авто-память — она пишет в служебные папки программы. Это **НЕ наша система**.

Наша память — только `MEMORY.md`, `memory/`, `knowledge/`. Веди записи только сюда.

---

## 🔒 Память переживает любое обновление

`MEMORY.md`, `memory/`, `knowledge/` дополняются по ходу работы, но не перезаписываются шаблонами при обновлении никогда.
