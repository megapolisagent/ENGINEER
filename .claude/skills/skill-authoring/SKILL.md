# Skill Authoring
## Writing and testing Skills as one discipline — TDD applied to process documentation

> Тестирование Skill'а — не отдельный шаг после авторства, а тот же цикл, что и его создание.

## Core principle

**Writing a Skill IS Test-Driven Development applied to process documentation.** Напиши сценарий под давлением (тест), убедись, что субагент без скилла проваливает его (RED), напиши скилл, убедись, что субагент со скиллом проходит проверку (GREEN), закрой лазейки (REFACTOR).

**Если ты не видел, как агент ошибается без скилла, ты не знаешь, учит ли скилл правильным вещам.**

## Iron Law

```text
NO SKILL WITHOUT A FAILING TEST FIRST
```
Применяется и к новым скиллам, и к правкам существующих. Написал скилл до теста? Удали и начни заново.

## When to create a Skill

**Создавать, когда:** паттерн неочевиден; навык будет многократно переиспользоваться между задачами; подход применим широко, а не в одном изолированном файле.

**Не создавать для:** разовых решений; стандартных практик среды; специфичных правил конкретного проекта (это место в `.claude/rules/`); механических ограничений, которые надежнее закрыть кодом валидации.

## The cycle

1. **Capture intent:** зафиксируй триггеры вызова (в каких ситуациях запускается) и ожидаемый формат выхода.
2. **RED (тест на провал):** запусти сценарий на субагенте БЕЗ скилла. Задокументируй дословно его ошибки и ложные оправдания.
3. **Write the SKILL.md:**
   - Frontmatter: `name` + `description` (только триггеры вызова, без пересказа самого сценария).
   - Тело `SKILL.md` — строго до 500 строк.
   - Таблицы запретов и явные красные флаги против ложных оправданий модели.
4. **GREEN (тест на успех):** запусти проверку с подключенным скиллом и сравни результат с baseline.
5. **REFACTOR (закрытие лазеек):** если модель находит обходные пути — добавь явный контр-аргумент в скилл и проверь снова.

## Structure (Progressive Disclosure)

```text
skill-name/
├── SKILL.md (обязательно — ядро до 500 строк с YAML-шапкой)
├── scripts/     — детерминированный исполняемый код (Python/Bash)
├── references/  — правила, схемы и документация, подгружаемые по требованию
└── examples/    — эталонные образцы и примеры решений
```

## Checklist

- [ ] Исходный провал (RED) зафиксирован дословно
- [ ] Описание в шапке (`description`) содержит только фразы-триггеры
- [ ] Успешный прогон (GREEN) проверен на идентичном сценарии
- [ ] Таблица ложных оправданий заполнена (для дисциплинарных правил)
- [ ] В теле нет ссылок на несуществующие файлы или внешнюю инфраструктуру
- [ ] Четко указано, когда скилл НЕ должен применяться
- [ ] Зарегистрирован в Skill System, проверена применимость к другим агентам экосистемы (Cross-Agent Matrix)
