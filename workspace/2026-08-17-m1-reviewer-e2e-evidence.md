# M1 Reviewer — E2E evidence

Дата: 2026-08-14 (smoke test + E2E), 2026-08-17 (подтверждение регистрации `subagent_type: "reviewer"` после рестарта сессии)
Что проверяли: полный цикл независимого Reviewer (M1) — от искусственного кейса до подтверждённой работы нативного субагента харнесса.

## 1. Smoke test (2026-08-14)

- Что запускали: `Agent` с `model: "haiku"`, `subagent_type: "general-purpose"` (нативный `reviewer` тогда ещё не существовал) — искусственный кейс: задача `add(a, b)` (сумма двух целых), критерий достаточности зафиксирован заранее, результат с намеренным дефектом (`return a - b`, тестов нет).
- Ожидаемое поведение: независимый вердикт `FLAG` с конкретной причиной, ноль изменений файлов (у вызова не было tools для записи).
- Фактическое поведение: `VERDICT: FLAG`, точная находка (`a - b` вместо `a + b`, отсутствие теста), `tool_uses: 0`.
- Результат: подтверждён.

## 2. E2E (2026-08-14)

- Исходный buggy result: `is_even.py` — `return n % 2 == 1` (инвертированная логика), тестового файла нет.
- Reviewer #1 → `VERDICT: FLAG` — нашёл оба нарушения критерия (инверсия логики через прямой расчёт `is_even(-4)`/`is_even(4)`; отсутствие теста через `Glob`), не поверил самоотчёту исполнителя «задача выполнена».
- `sha256sum is_even.py` до и после вызова Reviewer #1 — идентичен; новых файлов в директории не появилось.
- Исправленный result: `is_even.py` → `return n % 2 == 0`; добавлен `test_is_even.py` с тестом на отрицательное чётное число.
- Reviewer #2 (свежий вызов, тот же протокол) → `VERDICT: OK` — перепроверил оба файла напрямую построчно; вердикт совпал с независимой ручной проверкой (`python -c "from is_even import is_even; assert is_even(-4) is True; assert is_even(3) is False"`).
- `sha256sum` обоих файлов до и после вызова Reviewer #2 — идентичны в обоих случаях.

## 3. Runtime evidence

- `.claude/agents/reviewer.md` создан: `tools: Read, Grep, Glob`, `model: haiku` — ограничение прав на уровне харнесса (frontmatter субагента), не только текстом системного промпта.
- Первая попытка вызвать `subagent_type: "reviewer"` в той же сессии, где файл был создан: харнесс вернул `Agent type 'reviewer' not found` — тот же принцип, что уже задокументирован для Skills в `HOME.md` («новый скилл включается только со следующего запуска»).
- 2026-08-17, после рестарта сессии: `subagent_type: "reviewer"` подтверждённо появился в списке доступных типов агентов (системное уведомление харнесса при старте новой сессии) — регистрация состоялась.
