# Исходная задача (зафиксирована дословно, не редактируется впоследствии)

Первый реальный тест всей системы, построенной сегодня (Technical Passport + self-check + execution trace), на самой Engineer, не на суб-агенте.

Задача Engineer:

Объединить skill-creator + writing-skills в одну цельную способность «авторство и тестирование Skill».

Engineer обязан:
- самостоятельно сформулировать достаточный результат;
- изучить исходные Skills;
- при необходимости использовать Researcher/внешний research по своему Technical Passport;
- создать один связный Skill, а не механически склеить два;
- проверить его;
- сделать self-check по паспорту;
- завершить работу.

После этого смотрим не только на результат, но и на:
- что Engineer реально использовал;
- какие Skills/MCP/tools/models применил;
- соблюдал ли собственный паспорт;
- что сказал self-check;
- что показывает runtime trace;
- где self-check и runtime расходятся.

И только после этого решаем, нужно ли вообще что-то менять в Engineer.

Явная поправка владельца: не нужно отдельно, заранее доказывать, что живой trace собственной сессии можно достать — это часть исполнения теста. Если механизм не сработает — это и есть реальный GAP, не блокер для начала.

Источник: диалог с владельцем, 2026-08-12, продолжение серии решений об Engineering-ревизии Engineer/capability-аудите.
