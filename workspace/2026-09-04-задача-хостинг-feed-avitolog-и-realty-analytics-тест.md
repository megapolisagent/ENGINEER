# 2026-09-04 — Задача: закрыть выбор хостинга feed.xml у Авитолога + проверить realty-analytics API

## Слова владельца (дословно)

Владелец нашла реальный пример (`github.com/esstsu-bot/avito-feed`) — публикация `feed.xml`
через raw-ссылку на обычный GitHub-репозиторий, подключённую в личном кабинете Avito Pro как
источник автозагрузки. Это решает открытый пробел, честно зафиксированный при сборке Авитолога
(`ENGINEER/workspace/2026-09-01-статус-трафик-менеджер.md`: «хостинг feed.xml не выбран — три
варианта (GitHub Pages / S3 / сайт застройщика)»). Подтверждение: «да» на предложение (1)
зафиксировать GitHub raw URL как выбранный способ хостинга со ссылкой на этот реальный пример,
(2) проверить реальным вызовом API, включена ли на аккаунте функция `realty-analytics`
(`POST /realty/v1/report/create/{itemId}`).

## Критерий достаточности

1. `DECISIONS.md` Авитолога получает запись (Locked) — выбран способ хостинга: собственный
   git-репозиторий + raw-ссылка GitHub, с явной ссылкой на найденный реальный прецедент.
2. Реальный вызов `POST /realty/v1/report/create/{itemId}` на одном из настоящих активных
   объявлений аккаунта — зафиксирован фактический результат (включена фича или `featureDisabled`),
   не предположение.
3. Не создаю сам репозиторий/хостинг физически — это отдельное действие, требует решения
   владельца, где именно (её GitHub-аккаунт, публичный видимый репозиторий) — только фиксирую
   выбор механизма.
