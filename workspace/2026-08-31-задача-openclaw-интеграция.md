В качестве сервисного инструмента сбора мы рассматриваем open-source агентный фреймворк OpenClaw (в связке с локальными моделями через Ollama или Node.js runtime).

   - Как вызывать OpenClaw автономно (через CLI-команды, cron/heartbeat или скрипты-триггеры из терминала).

4. Инженерный план внедрения (Step-by-step):

## Инженерный план (2026-08-31, после находок Researcher) — только архитектура на бумаге, установка не запускалась

Владелец подтвердил формат «сначала архитектура, установку не трогать» и попросил включить в цель Avito/классифайды. Это решение не принято — граница ниже сужена обратно, юридический риск не меняется от смены инструмента (см. `OPEN_QUESTIONS.md`, 2026-08-31: собственная Acceptable Use Policy официального хостинга OpenClaw сама запрещает ровно этот сценарий).

### Граница цели

- **Входит**: открытая документация застройщиков на их собственных официальных сайтах — прайс-листы, ДДУ, регламенты, промо-акции (тот же тип данных, что сегодня вручную собран для Эталон Групп, `AI Avitolog/data/market_raw/2026-08-31-etalongroup-promotions.json`).
- **Не входит**: Avito и любые классифайды/агрегаторы третьих лиц — решение не пересматривается по формулировке задачи, тот же принцип, что уже зафиксирован в `AI Avitolog/DECISIONS.md`, 2026-08-31.

### Data Pipeline

`OpenClaw Gateway (Browser Skill, managed-профиль)` → навигация только по явному allow-list сайтов застройщиков → скачивание страницы/PDF → сохранение файлом в data-папку нужного агента:
- `AI Legal Constructor/data/legal_raw/<застройщик>/<дата>-<документ>.pdf`
- `AI Marketing Strategist` (или `AI Avitolog`) `/data/market_raw/<застройщик>/<дата>-promo.json` — только собственные материалы застройщика о своих объектах, не данные о конкурентах с Avito.

Дальше — без изменений: агент читает файл из своей `data/`-папки, как уже устроено сейчас (ручной прогон Avitolog сегодня это подтвердил). Прямого сетевого доступа у самих Legal Constructor/Marketing Strategist/Avitolog не появляется — OpenClaw работает отдельным процессом, кладёт файл, агент его читает постфактум.

### Guardrail, обязательный до добавления любого сайта в allow-list

Подтверждено Researcher: у самого OpenClaw нет встроенной проверки ToS/robots.txt целевого сайта — есть только сетевой SSRF-guardrail (другая задача). Значит проверка — ручная, до включения сайта:
1. Прочитать `robots.txt` сайта.
2. Прочитать пользовательское соглашение сайта на явный запрет автоматизированного сбора.
3. Только официальный сайт застройщика о собственных объектах — никогда агрегатор/классифайд третьей стороны.
Allow-list — явный список доменов в конфиге, не «весь интернет по ключевым словам».

### Установка (задокументировано по находкам Researcher, НЕ выполнено на этой машине)

- Требуется Node 22.22.3+ / 24.15+ / 25.9+ — версия на этой машине не проверялась в рамках этой задачи.
- На Windows нативный путь существует (PowerShell-инсталлятор), но фоновый безнадзорный режим (Scheduled Task) на 2026-08-31 имеет класс открытых, не закрытых issues (`OPEN_QUESTIONS.md`) — реалистичнее WSL2 для режима без присмотра, честно называю это компромиссом, не тишиной.
- Порядок команд (по документации, не проверено запуском): `openclaw install` → `openclaw gateway install` → `openclaw skills install` (Browser Skill).

### Автономный запуск — только после ручной проверки первого прогона

`openclaw automations add --cron "..." --session isolated --webhook <локальный endpoint>` — не включать cron/heartbeat до того, как минимум один прогон явно проверен человеком, не самим агентом, который его запустил.

### Первый тестовый пайплайн (план, не выполнено)

1. Один застройщик (Эталон Групп — уже частично собран вручную сегодня), один документ, не весь сайт целиком.
2. Ручной разовый запуск (`openclaw run`, не cron).
3. Результат сверяется человеком с тем, что уже собрано вручную сегодня (`AI Avitolog/data/market_raw/2026-08-31-etalongroup-promotions.json`) — совпадает содержательно или нет.
4. Только после совпадения — расширять на автоматический cron и других застройщиков, не раньше.

### Явно не входит в эту архитектуру

- Avito и любые классифайды/агрегаторы — исключено юридически, не пересматривается сменой инструмента.
- Отдельный агент-сборщик со своим `SOUL.md`/`HOME.md` — не нужен: OpenClaw здесь внешний сервис, пишущий файлы в уже существующие `data/`-папки уже существующих агентов, не разговорный агент со своим характером — нет причины изобретать новую персону под чисто техническую функцию (`repository-design`, тест «Foundation/профессия/привычка»).
