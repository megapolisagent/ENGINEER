# Engineering-ревизия Researcher (AI Intelligence) — отчёт

> Задача зафиксирована дословно: `2026-08-12-задача-researcher-remediation.md`. Ниже — что реально сделано, сверено повторной проверкой, не пересказ намерения.

## Что изменилось

- **Foundation-структура достроена**: `VISION.md`, `HOME.md` (роль делегирует в `MISSION.md`, не дублирует), `AGENTS.md`, `SOUL.md`, `PROFILE.md`, `MEMORY.md`, `ROUTING.md` (с реальными строками роутинга по существующим `knowledge/`-файлам), `OPEN_QUESTIONS.md`, `COMMUNICATION.md`, `instructions/memory-rules.md`, `workspace/`.
- **`UPDATE.md`/`update.sh` перенесены сразу в исправленном виде** — не оригинал Foundation. Оригинал стирает `HOME.md`/`AGENTS.md`/`ROUTING.md`/`skills/` целиком при обновлении (найдено и эмпирически подтверждено на Engineer, 2026-08-12); Researcher получила версию без этого дефекта, не унаследовала его повторно.
- **`skills/reverse-engineering/` упакован в `SKILL.md` + `references/`** — методология (`PRINCIPLES.md`/`METHODOLOGY.md`/`REVIEW_LOOP.md`) перенесена без единой правки содержания, сверено контрольными суммами до и после. Зарегистрирован в Skill System (`origin: own`, категория `RESEARCH`, статус `DRAFT` — честно, evidence не выдумано).
- **`.claude/settings.local.json`**: было 114 строк, стало 39 — убраны одноразовые команды, включая буквальные следы сборки самого Engineer (`mkdir -p "Engineer/agent"`, `mv .../ENGINEER/` и т.п.), оставлены повторно используемые разрешения (WebFetch-домены реальных источников исследований, mcp-инструменты, общие Bash-паттерны).
- **`.claude/settings.json`**: было 14 строк, стало 5 — убрана одноразовая `gh release create v2.0` и специфичные одноразовые curl к конкретному репозиторию завершённого расследования.
- **`CLAUDE.md` исправлен** — раньше вёл прямо в `MISSION.md`, минуя новый `HOME.md`; Claude Code ищет именно `CLAUDE.md` первым, разрыв нашла повторная проверка, не первый проход.
- **`DECISIONS.md` заведён с форматом Foundation** (включая собственный Foundation-шаблонный Proposal про поле «Последствия») **+ один новый Proposal** — явно поставленный, не решённый вопрос про отношение к инлайн-решениям `REVIEW_LOOP.md`.

## Что осталось нетронутым осознанно (Craft, не Engineering)

- Содержание `MISSION.md` — ни строки.
- Методология `reverse-engineering` (`PRINCIPLES.md`/`METHODOLOGY.md`/`REVIEW_LOOP.md`, теперь в `references/`) — перенесена файл-в-файл, не отредактирована.
- Весь `knowledge/` (`CAPABILITY_MAP.md`, `EVIDENCE_INDEX.md`, `MECHANISM_LIBRARY.md`, `MY_AGENTS.md`, `cases/`, `evidence/`) и `research/` — не реорганизованы, не переименованы.
- Существующие инлайн-решения `REVIEW_LOOP.md` — не перенесены в `DECISIONS.md`, вопрос оставлен `Proposal`, не решён за Researcher.

## Что не удалось привести к общей системе

- **tools/MCP-декларация**: `.mcp.json` реально не покрывает `mcp__firecrawl__*`/`mcp__exa__*`, которые Researcher реально использует (видно по сохранённым в permissions записям). Не исправлено — у меня нет проверенных данных о правильных launch-командах для этих серверов; дописать наугад значило бы выдумать конфигурацию, а не исправить находку. Это тот же класс вопроса, что был честно оставлен открытым и для `tool-selection` Engineer — там решился отказом от `.mcp.json` вообще, здесь решение другое: подождать точных данных, не гадать.
- **Автоматическая связь Engineer↔Researcher** — `COMMUNICATION.md` добавлен как честное описание отсутствия канала (по вашему явному условию), не как новый канал. Остаётся GAP на уровне Foundation, не решается Engineering-ревизией одного агента.

## Новые расхождения, обнаруженные по пути (не было в исходном плане)

1. `CLAUDE.md` вёл мимо `HOME.md` — исправлено (см. выше), но найдено только при финальной проверке, не при планировании.
2. Регистрация нового Skill в Skill System потребовала сначала создать для него каноническую папку на складе (`Skill System/skills/reverse-engineering/`) — этого шага не было в одобренном плане явно, он логически необходим для «Skills → приводим к общей системе», но стоит отметить: это первое добавление НОВОГО Skill в общий склад в этой сессии, не просто синхронизация существующего.
