# Research: интеллектуальное извлечение данных из паспортов РФ и выписок ЕГРН — локальные OCR vs Vision API

Дата: 2026-08-21
Статус: завершено (с явными пробелами данных, см. маркеры [УТОЧНИТЬ])
Контекст: AI Legal Constructor, Phase 1.1 — Tesseract промахнулся по цифрам кадастрового номера при распознавании выписки ЕГРН. Задача — понять, чем можно заменить/дополнить Tesseract.

## Легенда маркеров

- **ЗНАЮ** — подтверждено источником (документация вендора, GitHub-репозиторий, официальный бенчмарк).
- **ПРЕДПОЛАГАЮ** — логичный вывод из найденных данных, но не подтверждён напрямую источником (например, расчёт по официальной формуле токенов, а не измеренная цена).
- **[УТОЧНИТЬ]** — данных не нашёл; нужен собственный тест или дополнительный источник.

Главный вывод из всего исследования сразу: **ни для одного движка (локального или облачного) не нашлось прямого бенчмарка точности именно на паспортах РФ или выписках ЕГРН**. Все публичные бенчмарки — на общих документах (счета, отчёты, OmniDocBench) или на кириллице «в среднем». Это касается и Tesseract, который сейчас используется. Отсюда практический вывод в конце документа.

**Важная оговорка про облачные варианты, не про точность, а про закон**: паспортные данные — персональные данные по 152-ФЗ. Закон требует, чтобы ПДн граждан РФ обрабатывались/хранились на серверах, физически расположенных в России; использование зарубежных облаков без предварительной локализации не допускается¹⁷. Ни Anthropic (Claude), ни OpenAI (GPT-4o-mini), ни DeepSeek не предлагают сегодня российскую локацию обработки для этих vision-моделей [УТОЧНИТЬ, требует отдельной юридической проверки на актуальную дату]. Это значит: отправка фото паспорта в любой из трёх облачных API — вероятное нарушение 152-ФЗ, а не просто вопрос удобства. Именно поэтому решение изначально сделано локальным — это подтверждается независимо от вопроса точности.

¹⁷ cloud.ru, «152-ФЗ: Требования к хранению и обработке персональных данных» (https://cloud.ru/blog/152-fz)

## Блок 3. Три архитектурных варианта и рекомендация

### Вариант A — полностью локально (текущий путь, с апгрейдом движка)

Заменить Tesseract на связку: **PaddleOCR PP-OCRv5 mobile** (CPU-only, свободная лицензия, обучен на кириллице, кандидат №1 по совокупности «бесплатно + CPU + поддержка RU») как основной OCR-слой, плюс проверить **RussianDocsOCR** как специализированный парсер конкретно под паспорт/СНИЛС РФ (он целится именно в задачу владельца, но у него нет независимого бенчмарка и заявлены GPU-требования в README — нужно проверить, реально ли работает на CPU через `--device cpu`).
Дополнительно — усилить не только OCR, но и **валидацию поля**: кадастровый номер и номер паспорта имеют строгий формат (маска цифр/двоеточий для кадастрового номера, контрольные суммы для серии/номера паспорта) — regex-валидация уже частично есть в Phase 1.1, её стоит расширить и **подсвечивать пользователю поля с низкой уверенностью распознавания** вместо тихой автоподстановки. Это прямо бьёт по найденной проблеме (промах в цифрах) без изменения архитектуры вообще.
Отдельно для ЕГРН: если владелец/агент получает выписку **в электронном виде через личный кабинет Росреестра с ЭП**, документ приходит как подписанный PDF/XML со структурированными данными — кадастровый номер и площадь можно взять из XML без всякого OCR¹⁸. Это не работает для сканов «бумажной» выписки, но стоит проверить, какой процент выписок в реальном потоке агентства уже приходит в электронном виде.

¹⁸ astral.ru, «Как получить выписку ЕГРН с помощью электронной подписи»

### Вариант B — полностью облако (Vision API)

Выше по заявленному качеству на сложных/шумных фото (реальные бенчмарки on RU-паспортах не найдены, но общая архитектура VLM — это то же семейство моделей, что решает OmniDocBench на 88-96%, против отсутствия прямых цифр у Tesseract). Дешёво по деньгам (доли доллара на 100 документов). Но: персональные данные покидают компьютер пользователя и, по всей видимости, попадают на зарубежную инфраструктуру — то есть напрямую противоречит уже принятому осознанному решению владельца и создаёт риск по 152-ФЗ (штрафы за неправомерную передачу — до 25-50 млн ₽ за спецкатегории/биометрию¹⁹, паспортные данные — базовая категория ПДн, но с ужесточающимся регулированием). Не рекомендую как основной путь.

¹⁹ cloud.ru, «152-ФЗ в облаке»

### Вариант C — гибрид (локально + точечное облако с согласием)

Локальный OCR (Вариант A) обрабатывает документ полностью. Если конкретное поле (например, только кадастровый номер) распознано с низкой уверенностью, система: (1) вырезает **только этот фрагмент изображения** (не весь документ, не ФИО, не фото), (2) явно спрашивает согласие пользователя на отправку именно этого фрагмента в облако для конкретного документа, (3) отправляет только этот кроп в Vision API как «дозор» по одному полю.
Это снижает объём персональных данных, покидающих компьютер, но **не снимает риск по 152-ФЗ полностью** — сам факт, что кроп происходит из паспорта или выписки, всё ещё может квалифицироваться как обработка ПДн, если в кадре остаются фрагменты, привязывающие число к личности (например, часть кадастрового номера рядом с адресом). Это пограничный случай, который лучше не решать техническим самоволием, а обсудить с юристом агентства, прежде чем включать даже как опцию.

### Рекомендация

**Вариант A (доработка локального пути) — как основное направление.** Обоснование: единственный вариант без юридического риска по 152-ФЗ, при этом PaddleOCR PP-OCRv5 — бесплатная, CPU-совместимая, активно поддерживаемая замена Tesseract с заявленным (не независимо проверенным) приростом точности на мультиязычных/кириллических данных, а RussianDocsOCR целится именно в паспорт РФ. Плюс регекс/чексум-валидация и UI для подтверждения полей с низкой уверенностью — это устраняет корневую причину найденной ошибки (тихий промах в цифрах) независимо от того, какой OCR-движок используется.
**Вариант C — держать в кармане как опцию**, но включать только после отдельного разговора с владельцем и (по-хорошему) с юристом — не встраивать по умолчанию.
**Вариант B — не рекомендую.**

### Главная оговорка исследования

Ни один из вариантов не подтверждён числом **на реальных паспортах РФ и выписках ЕГРН** — все найденные бенчмарки общие (OmniDocBench, внутренние ELO-скоры, счета). Прежде чем что-либо менять в продакшене, стоит взять 10-20 реальных (или максимально похожих) тестовых сканов, прогнать через PaddleOCR PP-OCRv5 и, если доступно, RussianDocsOCR, и сравнить с текущим Tesseract на том же самом кейсе, где был промах в кадастровом номере — это единственный способ получить надёжную цифру именно для этой задачи.
