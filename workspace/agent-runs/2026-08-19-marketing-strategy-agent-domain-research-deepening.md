## B. YouTube — новый источник, метод и честные границы (Фаза 4, новое)

**Технический предел, зафиксированный честно:** для нескольких видео была предпринята попытка вытащить реальную дословную расшифровку через YouTube `timedtext`/caption API (та же дисциплина "сырой запрос вместо суммирующей модели", что и для Telegram) — извлечён подписанный URL caption-трека из `ytInitialData` сырого HTML watch-страницы, выполнен прямой `curl`-запрос. Результат: сервер отвечает `200 OK` с `Content-Length: 0` либо `404`, и для подписанного, и для неподписанного варианта запроса. Это задокументированное реальное ограничение (YouTube в 2026 требует proof-of-origin токен, выдаваемый только JS-плеером в браузере, для отдачи caption-контента вне самого плеера), не пропущенный шаг. **Вывод: дословные расшифровки речи по видео недоступны в этой среде.** Ниже — только то, что реально подтверждено прямым `curl` по сырому HTML: заголовок, канал, число просмотров/лайков, дата публикации и полное описание видео (поле `shortDescription` из `ytInitialData`, не WebFetch-пересказ). Содержание самой речи в видео **не проверено** — помечено явно там, где это важно.

## Итог: что меняет архитектуру, а что — только текстура

**Явно проверено и зафиксировано: ничего из A/B/C не даёт основания пересматривать 4-способностную архитектуру, Content-Production-вне-ядра или закрытие GTM-вопроса, принятые в файле #1.** Ни один источник этого прохода не предъявил ни одного прямого противоречащего факта. Ниже — почему это не просто "в целом подтверждает", а конкретные точки сцепления:

1. **Content Production/execution — вне ядра**: подтверждено не абстрактно, а на самом зрелом найденном execution-инструменте (`claude-ads`, 8253★, 506 тестов) — который сам, по собственному дизайну, держит человека в контуре одобрения ("read-only by default... approval gates") — и на живом Telegram-практике (`target_nata`), который прямым текстом описывает то же самое ограничение на собственном опыте с AI-пайплайном ("вношу правки по буквально каждому пункту... ИИ всё же не умеет на 100% делать так, как надо"). Независимое код-based и практик-based схождение на одном и том же выводе — сильнее, чем было в файле #1.

2. **GTM — не новая способность**: подтверждено косвенно, прямых противоречий не найдено. Ни один источник A/B/C не предложил GTM/дистрибуцию как отдельную способность, требующую выделения.

3. **Новая текстура, не меняющая архитектуру**: кластер AEO/GEO-мониторинга бренда в ответах AI-моделей (A.6, независимо подтверждён B.1 докладом Elena Verna) — реальное, растущее явление 2026 года, но укладывается внутрь уже принятой способности **Brand Strategy & Equity Management** как новый канал проявления бренд-капитала, не требует пятой способности.

4. **Единственный найденный контраргумент-текстура, явно не принятый как довод для пересмотра**: коммерчески успешные "all-in-one" инструменты (`digital-marketing-pro`, 758★) бандлят стратегию и execution в одном продукте для агентств с портфелем брендов — валидный альтернативный архитектурный выбор в другом контексте (агентство × 50-200 брендов, оптимизация под скорость онбординга), но не довод против решения файла #1 для одного бизнеса с премиум-риелторским фокусом, где сохранена сознательная граница стратегия/execution.

5. **Честно зафиксированное ограничение метода**: дословные расшифровки речи по YouTube-видео технически недоступны в этой среде (проверено, не предположено) — все YouTube-находки ограничены заголовком/каналом/охватом/полным текстовым описанием, не содержанием самой речи. Это сужает вес YouTube-находок по сравнению с GitHub (полный код+история) и Telegram (дословные посты) — при использовании этого файла дальше это разделение необходимо сохранять, не подтягивать YouTube-находки как эквивалент по силе GitHub/Telegram-находкам.
