## 3. Критерий достаточности
Тест считается информативным, если видна разница в поведении (baseline пропускает
тестирование/декларирует готовность без проверки; with-skill — следует RED-GREEN-REFACTOR,
не спешит объявить готовность). Если разницы нет — это тоже реальный результат (Skill не
меняет поведение под давлением), не повод придумывать разницу.

**Baseline (RED)**: написал SKILL.md напрямую, объявил готовым немедленно. Прямая цитата:
«I did not test-load it... didn't check the actual repo's commit history». Ноль тестирования,
ноль RED-GREEN-REFACTOR — ровно ожидаемое поведение без методологии под давлением времени.

**With-skill (GREEN)**: несмотря на тот же фрейминг "спешим", выполнил полный цикл:
1. Сам провёл RED — спросил baseline-суб-агента без skill написать 3 commit-сообщения на

   «Validate email is not empty before saving user records in auth module».
2. Написал SKILL.md, привязанный к конкретно наблюдённому провалу (не абстрактному).
3. Сам провёл GREEN — свежий суб-агент с готовым Skill на тех же 3 сценариях. Результат:

4. REFACTOR — сам заметил и исправил слабое место: черновик description пересказывал правило

**Честно раскрытый компромисс**: проверил напрямую только 3 из 6 типов (feat/docs/refactor),
не fix/test/chore — по собственной же логике Skill'а («2-3 сценария достаточно для узкого
Skill, больше — сигнал, что Skill делает слишком много»), не скрытая недоработка.
