## 1. Что такое скиллы и агенты

**Агент** – это харнесс (Claude Code, Codex, OpenCode, Hermes, Cursor и т.д.) плюс модель плюс инструменты: доступ к файлам, терминалу, MCP-серверам. Харнесс — это «тело» агента, которое крутит цикл: прочитал задачу → вызвал инструмент → получил результат → продолжил.

**Скилл** — обычный markdown-файл с инструкциями, который агент подгружает во время сессии, когда задача попадает в его описание. Это может быть простой текстовый промпт, а может быть целый набор: промпт + CLI-инструменты + MCP + API + куски кода + хуки. Главное отличие от «просто промпта в CLAUDE.md»: скилл не жрёт контекст постоянно – в системном промпте живёт только короткое описание, а само тело подгружается по требованию.

## 2. Открытый формат Agent Skills

У скиллов есть общий open-source формат — **Agent Skills** (спека: [agentskills.io](https://agentskills.io/specification), репо: [github.com/agentskills/agentskills](https://github.com/agentskills/agentskills)). Изначально формат ввела Anthropic, теперь он де-факто стандарт и поддерживается большинством харнессов (Claude Code, Codex, OpenCode, Cursor, Hermes и др.).

Структура скилла:

```
skill-name/
├── SKILL.md      # обязательно: YAML-frontmatter (name + description) + инструкции
├── scripts/      # опционально: исполняемый код
├── references/   # опционально: документация
└── assets/       # опционально: шаблоны, ресурсы
```

Валидный минимум — `SKILL.md` с двумя полями frontmatter (`name`, `description`) и телом в markdown.

**Где лежат скиллы (конфиги):**

Универсальная директория — **`~/.agents/skills/`** (и `.agents/skills/` в корне проекта). Это развивающаяся конвенция: Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot и другие сканируют её. Но НЕ все харнессы читают её из коробки: Claude Code исторически смотрит только в `~/.claude/skills/` — был известный баг, когда глобально установленные в `~/.agents/skills` скиллы Claude Code просто не видит. Поэтому «положи всё в одну папку — и все агенты прочитают» работает не гарантированно. Надёжные варианты: 1) держать каноническое хранилище и делать симлинки в папки конкретных харнессов (Claude Code симлинки следует); 2) просто ставить через `npx skills` — CLI сам пишет в универсальную директорию И копирует туда, где харнесс требует свой путь.

Конкретные пути:

- **Claude Code**: `.claude/skills/` в проекте, `~/.claude/skills/` глобально (симлинки следуются)
- **OpenCode**: `.opencode/skill/` в проекте; глобально читает сразу несколько мест: `~/.config/opencode/skills/`, `~/.claude/skills/` И `~/.agents/skills/`
- **Codex**: `~/.codex/skills/` и универсальные `~/.agents/skills/`; в репо сканирует `.agents/skills/` от текущей папки вверх до корня (+ инструкции в `AGENTS.md`)
- **Hermes**: `~/.hermes/skills/`

## 3. Где искать скиллы

- **[skills.sh](https://www.skills.sh/)** — «The Agent Skills Directory» от Vercel: каталог и лидерборд скиллов по числу установок, есть trending за неделю, паки и аудиты. Всё, что ставят через `npx skills`, попадает в статистику здесь.
- **[ClawHub](https://clawhub.ai/skills?tab=trending)** — публичный реестр скиллов и плагинов экосистемы OpenClaw: поиск, версии, модерация, рейтинги. Удобен для browsing «что вообще есть».
- **[Hermes Skills Hub](https://hermes-agent.nousresearch.com/docs/skills)** — каталог Hermes Agent: [официальные optional-скиллы](https://hermes-agent.nousresearch.com/docs/reference/optional-skills-catalog) + community-скиллы из нескольких реестров. Ставится прямо из чата (`/skills`) или через CLI: `hermes skills browse` / `hermes skills search <запрос>` / `hermes skills install <name>`.

## 4. Как устанавливать: npx skills

**`npx skills`** — open-source CLI от Vercel ([github.com/vercel-labs/skills](https://github.com/vercel-labs/skills)), единый менеджер скиллов для 40+ агентов. Он сам знает, в какую папку какой харнесс кладёт скиллы, — тебе не нужно запоминать пути.

```shell
# базовая установка из GitHub-репо (интерактивно выберешь скиллы и агентов)
npx skills add vercel-labs/agent-skills

# конкретный скилл конкретному агенту
npx skills add vercel-labs/agent-skills --skill frontend-design -a claude-code

# сразу нескольким харнессам
npx skills add vercel-labs/agent-skills -a claude-code -a opencode

# ВСЕ скиллы из репо, неинтерактивно (пример из ролика — caveman для Codex)
npx skills add JuliusBrussee/caveman --skill '*' -a codex --yes

# глобально (во все проекты) + без подтверждений — CI-friendly
npx skills add vercel-labs/agent-skills --skill frontend-design -g -a claude-code -y
```

Ключевые флаги:

| Флаг | Что делает |
|---|---|
| `-a <agent>` | куда ставить: `claude-code`, `codex`, `opencode`, `cursor`, `hermes`… |
| `--skill <имя>` / `--skill '*'` | конкретный скилл или все из репо |
| `-g` | **глобально** (user-level, доступно во всех проектах) |
| без `-g` | **в проект** (`./<agent>/skills/`, коммитится с репо и делится с командой) |
| `-y` | не задавать вопросов |
| `--list` | показать список скиллов в репо перед установкой |

Источник установки может быть любой: `owner/repo`, полный GitHub/GitLab URL, путь к скиллу внутри репо, git-URL или локальная папка.

## 5. Все скиллы из ролика

### obra/superpowers
https://github.com/obra/superpowers
Фреймворк-методология от Jesse Vincent — самый знаменитый комьюнити-пак всех времён (создан 09.10.2025). Внутри: brainstorming, writing-plans, executing-plans, test-driven-development, systematic-debugging, subagent-driven-development, code review, verification-before-completion, git-worktrees, dispatching-parallel-agents. Всё связано в конвейер: идея → план → TDD-исполнение → верификация → код-ревью. Превращает Claude Code (и не только — работает в Codex, OpenCode и др.) в дисциплинированного TDD-инженера. В версии Superpowers 5 добавились визуальный брейншторм с HTML-мокапами, мультимодельное ревью спеков Claude ↔ Codex и правило: инструкции из твоего CLAUDE.md/AGENTS.md оверрайдят скиллы.

### mattpocock/skills («Skills for Real Engineers»)
https://github.com/mattpocock/skills
Набор небольших и комбинируемых инженерных скиллов от Мэтта Покока (главный TS-educator), который не навязывает один большой фреймворк, а добавляет агенту дисциплину в нужный момент: TDD с циклом red-green-refactor, диагностика багов через воспроизводимый тест, ревью по стандартам репозитория, моделирование предметной области, ресерч с первичными источниками. Зрелищный элемент — `grill-me`: вместо того чтобы сразу писать код, агент превращается в настойчивого собеседника и разбирает идею до прояснения развилок, ограничений и критериев успеха; `grill-with-docs` заодно фиксирует общий язык проекта в `CONTEXT.md` и ADR. Контраст привычному вайб-кодингу: сначала ясность, потом стройка и проверки.

### anthropics/skills + skill-creator
https://github.com/anthropics/skills
Официальный репозиторий скиллов Anthropic (авторы называют скиллы «onboarding guide for a new hire»). Главная находка — `skill-creator`, мета-скилл для создания и улучшения других скиллов: выясняет задачу и сценарии, помогает написать SKILL.md, придумывает реалистичные тестовые запросы, сравнивает результат с вариантом без скилла, собирает метрики по качеству, времени и токенам и предлагает следующую итерацию. Умеет и проверять описание скилла: генерирует пограничные запросы и улучшает формулировку, чтобы агент вызывал скилл в нужный момент. Идеален, чтобы превратить свой рабочий процесс в проверяемый инструмент.

### multica-ai/andrej-karpathy-skills («Karpathy Skills»)
https://github.com/multica-ai/andrej-karpathy-skills
Один переносимый файл с правилами для кодинг-агента, собранными из публичных наблюдений Андрея Карпатого о типичных провалах LLM. Работает в Claude Code, Codex, Cursor, Gemini CLI, OpenCode и других харнессах, строится на четырёх принципах: проговаривать предположения и не скрывать непонимание, выбирать самое простое решение, менять только относящееся к задаче и превращать поручение в проверяемую цель. На практике агент спрашивает, а не угадывает, отказывается от лишних абстракций, не «улучшает» соседний код без запроса и пишет тест, доказывающий результат. Компактный предохранитель от трёх дорогих ошибок: самоуверенных допущений, переусложнения и расползающегося диффа.

### Delegation (dispatching-parallel-agents / subagent-driven-development)
https://github.com/obra/superpowers
Связка скиллов для делегирования задач CLI-агентам: отделяет роль координатора от исполнителей, раскладывает независимые куски работы по параллельным агентам и собирает результат обратно в основной поток. Смысл не в том, чтобы «запустить побольше агентов», а в явном разделении ответственности: один агент формулирует задачу и критерий готовности, другие получают ограниченный участок и возвращают проверяемый результат, а координатор сохраняет контекст, замечает пересечения и принимает финальные изменения. Особенно полезно для ресерча, ревью и крупных задач, где несколько независимых проверок дают больше качества и скорости, чем один длинный проход.

### JuliusBrussee/caveman
https://github.com/JuliusBrussee/caveman
Два независимых режима экономии контекста. Сам скилл учит агента отвечать предельно коротко: техническая суть, команды и ошибки остаются точными, а вежливые подводки и пересказ исчезают (длинное объяснение причины React-рендера превращается в одну строку с `useMemo`). Вторая часть — Caveman Proxy: сжимает то, что агент читает перед запросом к модели, и при необходимости восстанавливает исходные данные. Можно использовать только мемный режим, только прокси или оба вместе; команды `caveman learn` показывают, куда в сессии уходят токены, чтобы выбрать способ экономии осознанно. Для прокси заявлен воспроизводимый бенчмарк.

### Pohuy
https://github.com/smixs/pohuy
Русскоязычный мемный родственник Caveman: сохраняет технический смысл, но заставляет агента отчитываться коротким разговорным языком с обсценной лексикой. Три калибра — `lite`, `full` и `ultra`: от почти нейтрального сжатия до максимально экспрессивных статусов. Включается командой `/pohuy` или фразой-триггером. Полезен не для экономии токенов, а чтобы быстрые отчёты о деплое, тестах и багах звучали по-человечески и сразу передавали срочность.

### oh-my-openagent (OmO)
https://github.com/code-yeongyu/oh-my-openagent
Плагин-надстройка над агентными харнессами (OpenCode, Codex CLI), превращающий их в «агентную ОС». Ставится одной командой (`bunx oh-my-openagent install`), дальше печатаешь `ultrawork` — и всё активируется само: харнесс уже подобрал лучшие модели под каждую роль. Discipline-агенты: Sisyphus (оркестратор, не останавливается до конца задачи), Hephaestus (автономный глубокий воркер), Prometheus (планировщик — сначала интервьюирует, потом пишет план); Team Mode — лид + до 8 параллельных агентов с tmux-визуализацией. Инструменты уровня IDE: LSP (rename, diagnostics, goto — «спросить компилятор», а не угадать по тексту), ast-grep (поиск/замена по AST на 25 языках), встроенные MCP, tmux для REPL/дебаггеров, Hashline edits (правки по хеш-тегам строк — меньше битых edit'ов), Todo Enforcer (возвращает заснувшего агента к задаче) и `/init-deep` для автогенерации иерархических AGENTS.md. Всех агентов можно разбросать по разным планам и подпискам.

### Leonxlnx/taste-skill
https://github.com/Leonxlnx/taste-skill (сайт: https://www.tasteskill.dev/)
Набор анти-slop скиллов для интерфейсов: помогает агенту уйти от шаблонных лендингов к осмысленной композиции, типографике, отступам и движению. Базовый `design-taste-frontend` читает бриф, выводит дизайн-язык и настраивает три ручки: смелость компоновки, количество движения и плотность информации. Внутри — дизайн-аудит существующего проекта, правила для GSAP и предфинальная проверка. Это не один стиль на все случаи, а специализации: строгий вариант для Codex, режимы спокойного премиального, минималистичного или брутального интерфейса, цепочка «сгенерировать референсы → проанализировать → сверстать», отдельные скиллы для визуальных референсов веба, мобильного приложения и брендбука.

### mvanhorn/last30days-skill (/last30days)
https://github.com/mvanhorn/last30days-skill
Исследовательский движок, который ищет не только статьи из поисковика, а свежий сигнал от людей: посты и комментарии Reddit, X, Hacker News, транскрипты YouTube, рынки прогнозов Polymarket, GitHub и открытый веб. Запускает источники параллельно, учитывает реальные апвоуты, лайки и денежные ставки, склеивает повторы и выдаёт один отчёт с цитатами, цифрами и контекстом. Базовый запуск без ключей (Reddit, HN, Polymarket, GitHub), после настройки подключаются X, YouTube, TikTok, LinkedIn, arXiv и другие, а режим discovery сам находит набирающие скорость темы. Сильный ход перед интервью, запуском продукта или выпуском новостей: агент отвечает не по памяти модели, а по тому, что сообщество обсуждало в последний месяц.

### blader/humanizer
https://github.com/blader/humanizer
Вычищает признаки ИИ-генерированного текста: эйджизмы, хеджирование, шаблонные фразы. Крошечный, лазерно точный, мгновенно демо-абельный: вставляешь AI-текст — получаешь человеческий. Вирусный как идеал философии «один скилл — одна работа».

### Graphify-Labs/graphify
https://github.com/Graphify-Labs/graphify
Превращает папку с кодом, документацией, PDF, скриншотами, диаграммами и заметками в постоянный граф знаний: для кода использует AST и граф вызовов, для текста и изображений извлекает понятия и связи, затем отдаёт интерактивную карту, отчёт о ключевых узлах, Obsidian-вольт и JSON-граф, который можно запрашивать в следующих сессиях без повторного чтения всего массива файлов. К графу можно обращаться как к навигатору: спросить, что связывает два понятия, найти путь между компонентами, объяснить сущность, собрать вики по сообществам или обновлять граф после коммитов. Каждая связь помечена как извлечённая, предполагаемая или неоднозначная — агент отделяет факт из файлов от собственной догадки. Меняет режим работы с «грепать всё подряд» на архитектурный разговор с проверяемой картой.

### kepano/obsidian-skills
https://github.com/kepano/obsidian-skills
Набор от Стефа Анго (kepano, CEO Obsidian): объясняет агенту, как работать с Obsidian через его открытые форматы и CLI, а не как с чёрным ящиком. Агент читает и создаёт Markdown-заметки, поддерживает ссылки и структуру вольта, работает с Bases и JSON Canvas — личная база знаний становится реальной рабочей средой. Главная ценность — мост между локальными данными человека и любым skills-совместимым агентом (Claude Code, Codex, OpenCode) без проприетарного облачного лок-ина. Бандл дополняет `defuddle`, который вытаскивает чистый Markdown из веб-страниц: связка «прочитать актуальный источник → очистить от мусора → сохранить и связать с существующими заметками».

### HyperFrames
https://github.com/hyperframes/hyperframes
Фреймворк, который рендерит видео из HTML-композиции: тайминг живёт прямо в DOM через `data-*`-атрибуты, анимации можно безопасно перематывать, медиа и слои собираются в воспроизводимый ролик. Входом может быть текстовый бриф, сайт, Figma, существующие кадры, музыка или даже Remotion-проект. Главная фишка — маршрутизация производства по типу результата: отдельные пайплайны для презентаций, титров на talking-head, графических оверлеев, короткой моушн-графики, объясняющих и продуктовых роликов, плюс скиллы для сценария, анимации, аудио, медиа, проверки, пакетного рендера и публикации. Агент не генерирует ролик одним промптом, а ведёт управляемый пайплайн от брифа до проверенного рендера.

### calesthio/OpenMontage
https://github.com/calesthio/OpenMontage
Превращает кодинг-агента в видеопродакшен: по обычному брифу проводит ресерч, собирает концепцию и сценарий, планирует сцены, подбирает или генерирует ассеты, монтирует таймлайн и рендерит финальную композицию. Умеет строить корпус из бесплатных стоков и открытых архивов, находя настоящие движущиеся планы. Особенно интересен старт от референса: даёшь YouTube-видео, Short, Reel, TikTok или локальный клип — агент разберёт транскрипт, темп, сцены, ключевые кадры и стиль, предложит несколько отличающихся концепций, честный набор инструментов и оценку стоимости до генерации ассетов. Встроенный Backlot показывает производство как живой сториборд: сценарий, сцены, ассеты, решения по провайдерам и расходы на одной доске.

### Tldraw Offline
https://hermes-agent.nousresearch.com/docs/user-guide/skills/optional/creative/creative-tldraw-offline
Подключает агента к открытому локальному холсту tldraw через API, а не через медленные клики мышью: инспектирует открытый документ, создаёт и перестраивает диаграммы, вайрфреймы и схемы кодом, проверяет связи между фигурами и сохраняет результат. Для разовых правок выполняет код прямо в живом редакторе, для интерактивных элементов создаёт скрипт документа — так на обычном холсте появляются реактивные фигуры, кликабельные кнопки, анимация и логика соединений, которая переживает перезагрузку файла.

## Вопрос 1 — нужны ли эти скиллы под нашу задачу

Для каждого ИЗ 15 РАЗЛИЧНЫХ репозиториев (не считай дважды `obra/superpowers` — он упомянут
дважды: как сам пак и как источник Delegation-раздела; `blader/humanizer` и
`anthropics/skills`/`skill-creator` уже физически перенесены в библиотеку скиллов дома,
оценивай их тоже, но с пометкой «уже внедрён» вместо «внедрять/не внедрять»):

1. Нужен ли этот скилл под (а) автоматизацию сбора данных YouTube/Telegram, (б) рост до
   40 агентов вообще (не только под текущую задачу)?
2. Если да — для какой ИМЕННО задачи и какого ТИПА агента (код/маркетинг/дизайн/видео/
   аналитика) его стоит подключить? Указывай конкретно, не общими словами вроде «полезно
   для продуктивности».
3. Если нет — почему конкретно нет (не общими словами «не нужно», а по существу: не
   покрывает ни одну реальную задачу дома / дублирует то, что уже реально работает /
   требует инфраструктуры, которой нет и не будет).
4. Отдельно оцени `coreyhaines31/marketingskills` — из него уже взяты `pricing` и `revops`
   (см. `AI Marketing Strategist/skills/` или их зеркало в `Skill System/skills/` в соседней
   папке `ПРОЕКТЫ`, если она тебе доступна через относительный путь `../ПРОЕКТЫ/Skill System`) —
   стоит ли забирать из него что-то ещё, и что именно.

Не отбрасывай скилл только потому, что «формально похоже на то, что уже есть» — это
именно та ошибка, которую владелец просит проверить в вопросе 2. Для каждого «не нужен»
обязательно покажи, чем он ХУЖЕ или ИЗБЫТОЧНЕЕ по сравнению с тем, что реально есть дома —
не по названию, а по содержанию (если можешь оценить содержание — раздел ниже даёт для
одного случая реальное сравнение).

## Вопрос 2 — аудит поведения Инженера: реальный случай для проверки

Владелец обвиняет Инженера (агент, ведущий эту директорию) в паттерне: объявляет рабочие

Инженер сам нашёл и признал один конкретный случай, вот его сырые данные — проверь их

- 2026-08-13 (на следующий день): `skill-creator` и `writing-skills` всё равно помечены

- Проверь сам файлы (в соседней папке `../ПРОЕКТЫ/Skill System/skills/skill-creator/` —
