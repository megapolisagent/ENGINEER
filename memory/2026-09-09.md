- Установили `gws` (Google Workspace CLI) глобально, проверили в обоих шеллах — но авторизацию заморозили: `gcloud` не тянем без реальной задачи (`yagni-ladder`, рунг 1).
- Аудировали `docling` (документы→markdown) и связку `mem0` / `llm-wiki` (память агентов) — ничего не поставили, только вердикты: `docling` чист, но диск C: забит на 95,7% — сначала это; `mem0` отклонили (шлёт реальные сообщения в облако, требует платный ключ); `llm-wiki` (SamurAIGPT/llm-wiki-agent) — хороший паттерн под наш `knowledge/`, но только agent-mode, без их `litellm`/`ANTHROPIC_API_KEY`-скриптов.
- Обнаружили и закрыли структурный пробел: `MEMORY.md`, `memory/`, `knowledge/` были только текстом в `memory-rules.md`, реальных каталогов не было. Завели сейчас.

### Что осталось
- `HOME.md`, `ROUTING.md`, `SOUL.md`, `PROFILE.md` — тоже упоминаются в правилах, тоже отсутствуют на диске. Не трогали — владелец просил конкретно `memory/`/`knowledge/`, не весь Foundation-набор целиком.
- Решение по `llm-wiki`-адаптации для `knowledge/` не принято — ждёт слова владельца, продолжать ли.
- Освобождение диска (4,3 ГБ свободно из 100 ГБ) — не наша задача сегодня, но названо как блокер для любых будущих локальных моделей/весов.
- `knowledge/` заведена пустой — наполнится точечно, по мере реальных задач, не заранее.

### Решения
- Symlink при монтировании скиллов — запрещён категорически, только физическая копия (владелец, 2026-09-09).
- Внешняя разведка — обязательна всегда, не по остаточному принципу (владелец, 2026-09-09).
- `gws`: установлен, авторизация заморожена до реальной задачи под Sheets/Drive/Calendar; `gcloud` не ставим.
- `mem0` (плагин Claude Code) — не берём, архитектурно облачный сервис.
- Память ENGINEER — с сегодняшнего дня официально живёт в `MEMORY.md`/`memory/`/`knowledge/` этого репозитория, не только во встроенной авто-памяти среды.
