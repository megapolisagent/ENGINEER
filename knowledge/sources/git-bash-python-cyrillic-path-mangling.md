# Git-bash ломает кириллические пути при передаче в python3 -c

Category: problems_and_fixes

Дата: 2026-09-09

## Проблема

На Windows, в git-bash, при вызове `python3 -c "..."` изнутри Bash-heredoc: если в код встроен путь с кириллицей вида

```python
r'C:\Users\bogol\OneDrive\Рабочий стол\...'
```

скрипт падает с `FileNotFoundError`. Путь приходит в python в виде мусора вместо кириллицы, например:

```
/c/Users/bogol/OneDrive/������� ����/...
```

## Причина

Мусор возникает из-за конвертации POSIX-путей самим git-bash при передаче аргументов внешней программе (python) — **не** из-за кодировки самого python. Git-bash транслирует Windows-путь в POSIX-форму (`C:\...` → `/c/...`) и на этом шаге портит не-ASCII (кириллические) символы в имени.

## Обход (подтверждённый)

Один из двух вариантов:

1. **Не встраивать путь с кириллицей напрямую в python-код**, вызываемый из bash — передавать его через переменную окружения или аргумент командной строки, не как литерал внутри `-c "..."`.
2. **Использовать `grep`/`cat`/`Read`-инструмент вместо python** для файлов с не-ASCII путями, если задача — просто прочитать/найти содержимое, а не выполнить python-логику. Обычно это и есть правильный выбор — см. [[skills-lock-hash-algorithm]], где та же проблема обошлась переключением на bash-инструменты.

## Область применения

Специфично для связки Windows + git-bash + python3, вызываемого через `-c` с литеральным путём в коде. PowerShell-инструмент этой сессии обрабатывает пути иначе — проблема не переносится туда.
