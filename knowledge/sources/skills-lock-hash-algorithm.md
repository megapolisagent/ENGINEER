# skills-lock.json: как считается computedHash

Category: project_knowledge

Дата: 2026-09-09

## Факт

`skills-lock.json` (в корне ENGINEER, ведётся npm-пакетом `skills` / `vercel-labs/skills`, тот же инструмент стоит за [[find-skills-scope]]) хранит для каждого установленного скилла поле `computedHash`. Это **не** sha256 содержимого одного `SKILL.md`.

Реальный алгоритм (`local-lock.ts`, `computeSkillFolderHash`): sha256 по **путям и содержимому всех файлов** папки скилла на диске в момент установки, конкатенированных в отсортированном по relative-path порядке — путь тоже участвует в хеше (чтобы переименование ловилось), не только байты файла.

Отдельно есть **другой** алгоритм для глобального (`~/.agents/.skill-lock.json`) — там `skillFolderHash` берётся из GitHub Trees API (git tree SHA всей папки в репозитории), не пересчитывается локально. Два разных механизма хеширования в одном инструменте, не путать.

## Почему это всплыло

Прямой sha256 одного `SKILL.md` не совпадал с записанным `computedHash` — искали причину, чуть не решили, что это баг/подделка. Разгадалось только после прочтения исходников `vercel-labs/skills` (`local-lock.ts`, `skill-lock.ts`) — см. [[git-bash-python-cyrillic-path-mangling]] про одну из технических сложностей при этом расследовании (не решающую, но встретившуюся по пути).

## Область применения

Любая будущая сверка `skills-lock.json` на подлинность/актуальность — считать хеш по всей папке, не по одному файлу, и явно проверять, какой из двух lock-файлов (`skills-lock.json` в репозитории vs `~/.agents/.skill-lock.json` глобальный) смотрим.
