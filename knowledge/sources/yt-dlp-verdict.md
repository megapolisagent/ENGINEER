# yt-dlp — вердикт аудита

Category: decisions_and_constraints

Дата: 2026-09-09

## Что это по факту

`yt-dlp/yt-dlp` — форк `youtube-dl`, CLI-загрузчик видео/аудио с ~1800 поддерживаемых сайтов (не только YouTube). Метаданные проверены напрямую через GitHub API: 189 940 звёзд, 16 472 форка, активно поддерживается (последний коммит 2026-08-30, релиз `2026.08.19`), лицензия — The Unlicense (public domain). Всплыл в этой сессии как опциональная зависимость `[video]`-экстры у `graphify` (см. [[graphify-verdict]]) для транскрипции видео — там уже отклонён вместе со всей video-веткой.

## Security-профиль — проверен, не предположен

13 официальных security advisories в репозитории (GitHub Security Advisories API), устойчивый повторяющийся паттерн: RCE/command injection почти всегда через опасные опциональные флаги (`--exec`, `--netrc-cmd`) с подстановкой плейсхолдеров из метаданных скачиваемой страницы, плюс несколько случаев обхода санитации имени файла/расширения (тоже potential RCE) и утечка cookie через `curl`-загрузчик. Все — с патчами, ответственное раскрытие, не признак заброшенности — наоборot, признак того, что проект серьёзно относится к репортам. Но сам паттерн говорит однозначно: безопасно только без `--exec`/`--netrc-cmd` и на обновлённой версии; скачивание с недоверенного/чужого URL при этих флагах — реальная, не гипотетическая RCE-поверхность.

## Вердикт

Не устанавливать сейчас — не потому что инструмент плохой (наоборот, зрелый, гигантский, ответственно поддерживаемый), а потому что конкретной задачи под него в экосистеме сейчас нет: единственный повод, по которому он всплыл — опциональная video-ветка `graphify`, уже отклонённая целиком. Если в будущем появится реальная задача на скачивание/транскрипцию видео (для любого агента) — при установке: обновлённая версия, без `--exec`/`--netrc-cmd`, скачиваемый контент и его метаданные (включая производные имена файлов) — трактовать как untrusted per `.claude/rules/external-script-safety.md`, не как обычный локальный файл.
