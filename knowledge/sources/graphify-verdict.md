# graphify (Graphify-Labs/graphify) — вердикт аудита

Category: decisions_and_constraints

Дата: 2026-09-09

## Что это по факту

`/graphify` — скилл + Python-пакет (`graphifyy` на PyPI), строит граф сущностей по кодовой базе/докам/статьям/картинкам/видео: детерминированный AST-парсинг (tree-sitter, десятки языков, без LLM и ключа) для кода + опциональная семантика через `GEMINI_API_KEY` либо через субагентов самого хоста (не требует своего API-ключа по умолчанию — честнее mem0). 116k+ звёзд подтверждены напрямую через GitHub API. Телеметрии не найдено (прогреп `cli.py`/`install.py`/`llm.py`/`serve.py`/`__main__.py`).

## Реальные препятствия для установки как есть

1. Скилл сам вызывает `pip install`/`uv tool install` при первом запуске без вопроса владельцу — конфликт с `.claude/rules/external-script-safety.md`.
2. `graphify/skill.md` — 713 строк, выше нашего потолка в 500 (`skill-authoring`).
3. Есть готовый блок и флоу для автовписывания в проектный `CLAUDE.md` (`always_on/claude-md.md`) — у нас `CLAUDE.md` правится только явным ревью владельца.
4. Опциональный git-хук на автопересборку (`hooks.py`) — контролируемый (уважает `core.hooksPath`, предупреждает), но всё равно требует отдельного решения перед установкой, не «раз в комплекте — можно».
5. Заявлен сразу на 16 AI-ассистентов — под нашу задачу нужен только вариант для Claude Code; взять «целиком» (канон `CLAUDE.md` §7) значит тащить 15 лишних `skill-<host>.md`.

## Сравнение с нашим knowledge-wiki

Не конкурент, другая задача: `knowledge-wiki` — рукописная растущая память решений по ходу работы; `graphify` — разовая (или `--update`) индексация уже существующего большого чужого корпуса с автографом связей. Пересекается по смыслу с [[domain_knowledge_retrieval]] — по сути более лёгкая альтернатива LightRAG (не требует своей инфры для кода), тот же порог пересмотра применим.

## Вердикт

Не устанавливать сейчас — не Champion-замена knowledge-wiki (другая ниша), и в текущем виде не проходит конвейер без правок (пункты 1-5 выше требуют отдельных явных решений владельца перед первым реальным запуском). Технически не грязный (Apache/MIT, без телеметрии) — если возникнет конкретная задача «разобраться в большом незнакомом репозитории», разумный кандидат вернуться и пройти полноценный PDR с этими пятью пунктами уже как чек-лист, не с нуля.
