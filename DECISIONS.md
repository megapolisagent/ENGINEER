# История и статус решений

> Не журнал. Действующий механизм: `HOME.md` и `UPDATE.md` обязаны сверяться с этим файлом в определённых сценариях, а не просто могут его почитать при желании.

## Как решение становится фактом

```
Proposal → Discussion → Locked
```

Переход между статусами разрешён только по явному подтверждающему слову владельца («принимаем», «фиксируем», «зафиксируй», «LOCKED») — никогда не выводится из тона реплики и никогда из того, что идею предложил сам владелец.

## Правила

- **Отклонённые альтернативы не удаляются.** Остаются в записи со статусом «отклонено» и причиной — защита от повторного предложения того же самого без нового аргумента.
- **После Locked — заморозка.** Обсуждение отклонённых вариантов прекращается немедленно. Снять заморозку может только явная команда владельца или прямой провал уже принятого решения на практике.
- **Решение не пересматривается без нового факта.** Следующий шаг конкретизирует и исполняет уже принятое, а не переоткрывает его заново. Работа, которая переживёт текущий диалог или затронет файлы устава — сначала короткая формулировка цели и границ, потом правки.
- **Высокий радиус поражения — пропорциональная проверка.** Решения, меняющие методологию работы агента, требуют проверки до Locked, но глубина проверки должна соответствовать масштабу и риску изменения. Для небольшого, чётко ограниченного изменения достаточно проверки владельцем и проверки на реальной задаче. Для изменений, затрагивающих фундаментальную архитектуру, роли, governance или большое число агентов, требуется независимая проверка отдельным изолированным ходом рассуждений. (Изменено 2026-08-13 — см. `Foundation/04_REPOSITORY/DECISIONS.md` того же дня, источник правки. Записи ниже, датированные до 2026-08-13, отражают прежнюю формулировку правила и не переписываются задним числом.)

## Кто и когда обращается к этому файлу

- **Перед новым предложением** — агент проверяет, не Locked ли это уже и не отклонялось ли раньше с обоснованием.
- **Перед правкой агентом собственных файлов устава** (`HOME.md`, `SOUL.md`, `ROUTING.md`) — обязательное чтение, см. `UPDATE.md`.
- **По прямому вопросу владельца** — «что мы решили по X».
- Рядовые задачи, не прошедшие входной фильтр по значимости, записи здесь не создают и сверяться с файлом не обязаны.
- Не читается при каждом старте сессии — как и дневник в `memory/`, это не часть капнутого уровня-1.

### 2026-09-04 — Proposal: регламент безопасного сбора данных (Авито, застройщики, Telegram, last30days)

Статус: Proposal
Что решается: владелец потребовала честно проверить, где локальный контур технически/юридически
откажется работать (robots.txt, политика платформ), и свести это в один регламент, включая Авито.
Проверено технически, не по памяти:
- **Avito**: `curl -A "Mozilla/5.0" https://www.avito.ru/robots.txt` — сам файл не запрещает обход
  большинству User-Agent (правила точечные: Yandex-специфика, отрезание UTM/трекинг-параметров).
  Реальный барьер — не robots.txt, а поведенческая антибот-защита QRATOR (уже подтверждено
  реальным `curl`-тестом Researcher, 2026-09-04: `429`+капча без браузерных заголовков, чистый
  `200` с ними). Правовой барьер — ст. 272 УК РФ / ToS п.2.4, за обход именно этой защиты,
  независимо от инструмента (Locked, 2026-08-31 и подтверждено сегодняшним разбором Firecrawl).
  Легальный канал уже используется — Avito Business API (Autoload/Messenger/Promotion,
  Авитолог) + официальная «Аналитика спроса» (~4000₽/мес, найдено Researcher 2026-09-04).
- **Официальные сайты застройщиков** (`AI Avitolog/instructions/open-site-access.md`) —
  разрешено (Locked, 2026-08-31): собственный сайт застройщика о своих объектах, не агрегатор.
  Правило НЕ проверяет `robots.txt` по каждому новому домену автоматически — это пробел,
  регламент ниже его закрывает.
- **Telegram-каналы** (`telegram-research`, curl на `t.me/s/<handle>`) — это собственный
  публичный preview-путь Telegram, не обход защиты. `curl -A "Mozilla/5.0" https://t.me/robots.txt`
  → `404` (файла нет вообще, никакого запрета). Ниже риска, чем Avito — не антибот-защищённый
  ресурс, Telegram сам отдаёт эту страницу без входа.
- **`last30days-skill`** (`AI Intelligence`) — источники неоднородны по риску, важное различие,
  найденное построчным чтением `SKILL.md`:
  - Reddit/HN/Polymarket/GitHub — «работают из коробки», через открытые/публичные API этих
    платформ — низкий риск, санкционированный путь.
  - YouTube — через `yt-dlp` (не официальный YouTube Data API) — технически широко
    используемый, юридически серая зона (ToS YouTube ограничивает автоматический доступ вне API).
  - X/Twitter — через извлечение **собственных cookie браузера владельца** (её реальная
    сессия, не официальный API) — тот же класс риска, что YouTube.
  - TikTok/Instagram (опционально, через ScrapeCreators) — сторонний платный скрейпинг-сервис,
    риск частично переносится на него, но метод в основе тот же класс.
  - Скилл сам требует явного разговорного согласия владельца перед extraction cookie
    (`"Consent must be conversational"`, зафиксировано в его же тексте) — не тихо.

Предлагаемый регламент (три уровня, не один общий «можно/нельзя»):

**Уровень A — санкционированный, использовать свободно:** Avito Business API + Аналитика
спроса; официальные сайты застройщиков (после проверки `robots.txt` конкретного домена —
делать это явно перед первым обращением к новому домену, не только проверять «это застройщик
или агрегатор»); Telegram публичные превью-страницы; Reddit/HN/Polymarket/GitHub через
`last30days-skill`.

**Уровень B — технически рабочий, юридически серый, использовать осознанно:** YouTube через
`yt-dlp`, X/Twitter через cookie-сессию владельца — не автоматизировать без её явного
согласия на КАЖДЫЙ первый запуск нового окружения (скилл это уже встроил сам), не превращать
в фоновый частый cron без отдельного решения о частоте — риск растёт с масштабом и частотой,
не с фактом использования один раз.

**Уровень C — никогда, независимо от инструмента:** автоматический обход технической
антибот-защиты Avito (или любого другого явно защищённого ресурса) любым способом, включая
более технически совершенные инструменты (Firecrawl, headless-браузер и т.п.) — сложность
инструмента не меняет юридической оценки самого действия обхода.

Отклонённые альтернативы: единое правило «Авито — нельзя, остальное — можно» — отклонено,
скрывает реальную неоднородность риска внутри «остального» (YouTube/X через yt-dlp/cookies
не то же самое по риску, что Reddit через открытый API); полный запрет YouTube/X-источников
last30days — отклонено, риск реален, но не запретительный, скилл уже встроил явное согласие.
Источник: `AI Intelligence/knowledge/evidence/2026-09-04-avito-market-data-legal-channels-vs-scraping.md`;
`AI Avitolog/instructions/open-site-access.md`; `AI Marketing Strategist/skills/telegram-research/SKILL.md`;
`AI Intelligence/skills/last30days-skill/SKILL.md`; прямые curl-проверки robots.txt, 2026-09-04.
