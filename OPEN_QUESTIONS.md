# Реестр открытых вопросов

> Не то же самое, что решение. Решение — выбор среди альтернатив, который утверждает владелец явным словом (см. `DECISIONS.md`). Открытый вопрос — пробел в знании, который закрывается доказательством, а не одобрением.

## Когда здесь появляется запись

Не для всего подряд — только для вопроса, который нельзя закрыть прямо сейчас парой уточняющих слов у владельца (для этого есть «Вход в задачу» в `HOME.md`). Здесь — то, что требует исследования, времени или внешнего события.

## Правило

Критерий ответа фиксируется **до** начала поиска, не после. Иначе легко принять слабый ответ задним числом, подогнанный под то, что хотелось найти.

Куда искать ответ — не дублируется здесь, см. классификацию потребности в `ROUTING.md`.

## Статус

Как и в `DECISIONS.md`: запись не удаляется, только переклассифицируется. Закрытый вопрос остаётся в файле со статусом «закрыт» и ссылкой, где теперь живёт ответ (`MEMORY.md` / `knowledge/*`). Вопрос может быть явно переоткрыт — с датой и причиной, если закрытие оказалось ошибочным.

## Формат записи

```
### {дата} — {вопрос коротко}

Статус: Открыт / Закрыт / Переоткрыт
Вопрос:
Что считать ответом (зафиксировано до поиска):
Ответ (если закрыт):
Где теперь живёт ответ:
```

## Журнал

### 2026-08-11 — Существует ли универсальный Exit Gate у AI-агентных систем

Статус: Закрыт
Вопрос: существует ли у AI-агентных систем, независимо от специализации, сходящийся, независимо подтверждённый механизм проверки «достаточно ли доказательств, чтобы объявить работу завершённой» — по функции симметричный входному триажу (Entry Gate), но на выходе?
Что считать ответом (зафиксировано до поиска): ≥2 независимых источника с одним и тем же по функции механизмом → универсальность подтверждена, есть основание для Foundation. Только фрагментированное/доменно-специфичное → остаётся зоной специализации. Ничего релевантного → статус «исследовано, ответа нет», не повод изобретать самим.
Ответ (если закрыт): Мировая практика подтверждает паттерн — 4 независимых источника, проверенных Researcher прямым fetch, сходятся на одной функции (самозаявленное агентом завершение не доказательство; переход в «готово» требует свежего механически проверяемого доказательства; его отсутствие блокирует переход безусловно). Критерий (≥2 источника) выполнен с запасом. Это закрывает только исследовательский вопрос «существует ли паттерн в мире» — решение, вносить ли механизм в Foundation, отдельное и не принято.
Где теперь живёт ответ: `knowledge/foundation-observations.md`, запись 2026-08-11 «Exit Gate: мировая практика подтверждает паттерн».

### 2026-08-12 — Соответствует ли чек-лист `repository-design` реальной практике AI agent engineering

Соответствует ли то, как Engineer определяет «готовность» агента и ищет в нём разрывы, реальной практике опытных AI agent engineers — не теоретическим фреймворкам? Пропущены ли в чек-листе категории, которые практика считает важными?
Что считать ответом (зафиксировано до поиска): конкретные пункты «подтверждено практикой / отсутствует в чек-листе», каждый с источником — не менее одного подтверждённого источника на пункт. Общая оценка без конкретики («выглядит нормально») ответом не считается. Ничего релевантного не найдено → статус «исследовано, ответа нет», не повод считать чек-лист автоматически достаточным.
Ответ (если закрыт): Критерий выполнен. 3 пункта чек-листа подтверждены практикой с источниками (честный пустой PROFILE.md, Skills только через installer, разделение «чек-лист пройден» от «сверено на реальной задаче»). Найдено 3 категории, которые чек-лист системно не проверяет: least-privilege/allowed-tools, воспроизводимый (перезапускаемый) eval, структурная независимость producer≠reviewer. Закрытие вопроса означает только «исследовательский вопрос получил достаточный ответ» — не решение вносить эти три категории в `repository-design`. Это отдельный, ещё не принятый шаг.
Где теперь живёт ответ: `knowledge/repository-design-observations.md`, запись 2026-08-12.
