# Technical Passport — шаблон

> **Статус: PROPOSED, не Locked.** Собран из трёх механизмов, зафиксированных 2026-08-12 (`LIFECYCLE.md`: независимый Reviewer / M1; Technical Execution Record — task_id → session_id → execution trace) плюс обсуждения про self-check. Не проверен на реальной сборке агента. Переходит в Locked после первого реального прогона — не раньше.

Заполняет Engineer при запуске **любого** агента (Researcher, будущий Tutor/Designer, временный воркер под одну задачу) — не только Researcher. Копия конкретного запуска сохраняется в `workspace/agent-runs/<task_id>.md`, не редактируется после запуска — тот же принцип, что у зафиксированной исходной задачи (`LIFECYCLE.md`, «Исходная задача как зафиксированный первичный артефакт»).

## 4. Обязательный формат финального отчёта агента (self-check)

Агент обязан вернуть Engineer ровно в этой структуре — не свободной прозой, чтобы сравнение с runtime trace было механическим, не разбором текста. Две части ниже (A и B) — разные проверки, не одно и то же: агент может идеально исполнить паспорт и всё равно дать плохой результат.

```
Статус: DONE / PARTIAL / BLOCKED

A. Исполнение паспорта (раздел 2 — что должен был делать):
✓/✗ <обязательный Skill 1>
✓/✗ <обязательный tool/MCP 1>
✓/✗ модель — та, что задана
✓/✗ порядок соблюдён (если был важен)
✓/✗ ограничения соблюдены

B. Результат (раздел 3 — критерий достаточности):
✓/⚠/✗ <по каждому пункту критерия отдельно>

Результат:
<краткий итог + путь/ссылка на фактический результат — сам результат остаётся там, где агент его создал, не копируется сюда целиком>
```

### Прогоны M1 Reviewer по значимым шагам (`LIFECYCLE.md`, «Расширение M1»)

Одна строка на каждый значимый шаг high-задачи, заполняется по мере прохождения, не задним числом. FLAG блокирует переход к следующему шагу (gating); после фикса — ровно один обязательный повторный прогон; повторный FLAG на том же шаге (включая несогласие Engineer) — эскалация владельцу через «Стоп-условие», не третья попытка.

| Шаг (артефакт/состояние) | Критерий достаточности (зафиксирован до вызова) | Вердикт #1 | Фикс + повторный прогон | Вердикт #2 (если был) | Эскалация владельцу |
|---|---|---|---|---|---|
| | | OK/FLAG | да/нет | OK/FLAG | да/нет |

Финальный прогон M1 в шапке раздела и последняя строка этой таблицы не дублируют друг друга: финальный прогон — проверка против исходной задачи целиком (тот же M1, Locked 2026-08-12); строка таблицы — конкретно последний значимый шаг. Для рядовой (не high) задачи таблица не заполняется — Entry Gate её туда не пускает.

## Почему именно так

- **task_id** — для корреляции с execution trace без самоотчёта агента (`LIFECYCLE.md`, «Technical Execution Record»), проверено экспериментом.
- **Self-check по структуре паспорта, не прозой** — чтобы расхождение с trace было видно сразу (реальный пример того же дня: самоотчёт «4 Bash», trace показал 6 — не обман, но неполно).
- **Исполнение паспорта (A) и результат (B) разделены визуально, не одним списком** — это два разных вопроса: соблюдение контракта и качество работы независимы друг от друга.
- **Результат в отчёте — краткий итог + путь, не сам результат** — паспорт остаётся инженерным контрактом, не контейнером для текстов/файлов/картинок, которые агент произвёл.
- **Незакрытые вопросы — обязательный, отдельный пункт** — особенно важно для Researcher: красиво написанный отчёт не считается завершённой работой, если осталось неизвестное.
- **Критерий достаточности до запуска** — то же правило, что уже действует для `OPEN_QUESTIONS.md` и для Reviewer: если критерий пишется после результата, он подгоняется под результат.
- **М1 Reviewer только после того, как паспорт подтверждён выполненным** — не раньше. Соответствие паспорту (техническое исполнение) и качество результата — два разных вопроса, не смешивать (см. обсуждение «два типа проблем» в этом же диалоге).

## Что не решено этим шаблоном

- Как именно `task_id` физически попадает в промпт агента, если агент запускается не через `Agent`-инструмент Engineer, а как полностью самостоятельная, отдельно открытая сессия — не проверялось.
- Формат `workspace/agent-runs/` — папка ещё не создана, появится при первом реальном использовании, не заранее.
