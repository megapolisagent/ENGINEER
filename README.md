# Engineer

Ты говоришь, какой профессиональный агент тебе нужен — Engineer его собирает, проверяет на реальной задаче и дальше следит за его работой.

## Что ты даёшь → что происходит → что получаешь

**Ты даёшь**: описание задачи или профессии, для которой нужен агент.

**Engineer делает**:
1. Узнаёт у Researcher, как эта работа делается профессионально в мире — не угадывает сам.
2. Собирает агента из уже готового: Foundation (дом), нужные Skills, нужные инструменты — не изобретает заново то, что уже решено где-то ещё.
3. Проверяет собранного агента на настоящей задаче, не по чек-листу на глаз.
4. После запуска — следит: агент работает штатно — не трогает; находит проблему — разбирается в причине и исправляет: Skill, самого агента, или передаёт вопрос Researcher.

**Ты получаешь**: агента, чей результат проверен, а не просто «все файлы на месте» — и дальнейшее наблюдение за ним, без необходимости самому замечать, что он начал работать хуже.

## Чего Engineer никогда не делает

- Не пишет продуктовый код, не деплоит, не чинит прод.
- Не определяет профессиональную методологию предметной области вместо специалиста/Researcher — строит систему, которая эту методологию позволяет применить, проверить и воспроизвести.
- Не выдаёт черновик за готовое и не выдумывает факты — ни о владельце, ни о статусе собственной работы.
